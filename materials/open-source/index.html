Strategische Option

Open Source bewusst nutzen

Nicht aus Prinzip. Sondern dort, wo es sinnvoll ist.

Open Source ist kein Selbstzweck und nicht für jede Anwendung automatisch die beste Lösung. Ein gutes kommerzielles Produkt kann die bessere Wahl sein, wenn es den Bedarf zuverlässig abdeckt, professionell betrieben wird und die Kosten im Verhältnis zum Nutzen stimmen.

Trotzdem lohnt es sich für Hochschulen und öffentliche Institutionen, Open Source aktiver als strategische Option zu betrachten. Nicht nur beim Veröffentlichen eigener Software, sondern auch bei der Frage, welche bestehenden Lösungen übernommen, angepasst oder gemeinsam weiterentwickelt werden können.

Der Bund hat diese Richtung deutlich gestärkt. Nach Art. 9 EMBAG soll von Bundesbehörden entwickelte Software grundsätzlich als Open Source veröffentlicht werden; bei der Nutzung bestehender Software wird Open Source ausdrücklich gleichwertig zu proprietärer Software behandelt. Die Bundesverwaltung unterscheidet dabei zwischen Konsumation, Kontribution und Kreation von Open Source.

Warum Open Source interessant sein kann

Der erste Vorteil ist Wiederverwendung. Wenn eine gute Lösung bereits existiert, kann es effizienter sein, sie zu prüfen, zu übernehmen oder weiterzuentwickeln, statt bei null zu beginnen oder für jedes Problem ein neues Produkt zu beschaffen.

Ein zweiter Vorteil ist Unabhängigkeit. Bei Open Source bleibt der Quellcode verfügbar. Eine Organisation kann nachvollziehen, wie eine Lösung funktioniert, eigene Anpassungen vornehmen, einen anderen Dienstleister beauftragen oder den Betrieb anders organisieren. Das schafft Optionen und kann Abhängigkeiten reduzieren.

Diese Frage gewinnt zusätzlich an Bedeutung, weil digitale Souveränität ein Schwerpunkt der Strategie Digitale Schweiz ist. Der Bundesrat beschreibt dabei ausdrücklich die wachsende Abhängigkeit von privaten Technologieanbietern und technologisch dominanten Staaten als strategische Herausforderung.

Ein dritter Vorteil liegt in Transparenz und Lernfähigkeit. Offener Code kann überprüft, verglichen und verbessert werden. Für Hochschulen ist das besonders interessant, weil Software nicht nur Infrastruktur, sondern häufig auch Teil von Forschung, Lehre und institutionellem Wissen ist.

Auch die ETH Zürich unterstützt Open Source ausdrücklich, weist aber gleichzeitig darauf hin, dass die Entscheidung für ein Open-Source-Modell sorgfältig geprüft werden muss. Ziele, Lizenzierung, mögliche spätere Kommerzialisierung und Kooperationen sollten früh geklärt werden.

Eine besondere Chance: gemeinsam statt mehrfach lösen

Wo mehrere Hochschulen oder öffentliche Institutionen ähnliche Probleme haben, entsteht ein zusätzlicher Hebel. Eine bestehende Lösung kann gemeinsam geprüft werden, Erfahrungen lassen sich teilen, Security- oder Architekturfragen müssen nicht mehrfach beantwortet werden und Weiterentwicklungen können dort gebündelt werden, wo tatsächlich gemeinsamer Bedarf besteht.

Diese Zusammenarbeit ist aber nur eine mögliche Form. Open Source kann genauso sinnvoll sein, wenn eine einzelne Hochschule eine bestehende Lösung übernimmt, wenn ein Dienstleister darauf Services anbietet oder wenn eine Institution ihre eigene Entwicklung so veröffentlicht, dass andere später davon profitieren können.

Open Source ist nicht automatisch günstiger

Offener Code beseitigt keine Arbeit. Eine ernsthaft betriebene Lösung braucht weiterhin Entwicklung, Wartung, Security, Releases, Dokumentation, Product Management und Support.

Deshalb kann Open Source auch ganz selbstverständlich kommerzielle Leistungen einschliessen. Eine Hochschule kann Software selbst betreiben, gemeinsam mit anderen weiterentwickeln oder Entwicklung, Integration, Support und Betrieb bei einem Dienstleister einkaufen.

Entscheidend ist nicht, ob Geld fliesst, sondern wo die Abhängigkeit liegt und wem die entstandene Lösung langfristig zur Verfügung steht.

Deshalb braucht es eine bewusste Entscheidung

Open Source ist besonders interessant, wenn eine bestehende Lösung wiederverwendet werden kann, Anpassbarkeit wichtig ist, langfristige Abhängigkeiten reduziert werden sollen oder mehrere Akteure ein ähnliches Problem lösen.

Es ist weniger attraktiv, wenn ein Marktprodukt den Bedarf deutlich besser und wirtschaftlicher erfüllt, wenn niemand die langfristige Verantwortung für das Projekt übernehmen kann oder wenn eine offene Lösung nur deshalb gewählt wird, weil sie vermeintlich «gratis» ist.

Für Hochschulen kann Open Source dabei mehrere Dinge gleichzeitig ermöglichen: bestehende Lösungen wiederverwenden, Wissen erhalten, Abhängigkeiten reduzieren, externe Anbieter flexibel einbinden und – wo es passt – gemeinsam mit anderen Institutionen investieren.

Die eigentliche Frage

Nicht:

Open Source oder kommerziell?

Sondern:

Wo schafft Offenheit für uns einen echten strategischen Vorteil – und wo ist eine andere Lösung sinnvoller?
