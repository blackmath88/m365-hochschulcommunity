# Open Layers — Visual Working Identity

**Status:** working identity, not an official brand.

## Idea

Open Layers describes the M365 Hochschulcommunity as a shared working and knowledge layer between autonomous institutions.

> **The individual parts remain visible; the common layer creates direction.**

The identity should feel like research, infrastructure and editorial design rather than a software vendor, association or marketing campaign.

## Mark

The central visual element is a modular chevron built from independent parts. The modules remain visible; together they create one forward direction.

The chevron represents:

- autonomy
- connection
- exchange
- modularity
- openness
- forward movement

It is a flexible graphic element, not a mandatory corporate logo. It can appear small beside the wordmark, cropped at page edges, enlarged on covers, or broken into modules for diagrams and project markers.

### Geometry

Canonical mark viewBox: `0 0 120 100`.

The construction uses four straight-edged ribbon modules. No rounded corners, gradients, strokes, shadows or 3D effects.

The full-colour mark uses three effective depths:

- rear: Mint / Soft Green
- middle: Jade
- front: Deep Green

The overlap should read clearly in screen and print output without relying on browser-specific transparency blending.

### Clear space

Use roughly one ribbon thickness of clear space around the standalone mark.

In a horizontal lockup:

- mark → divider: ~0.75 ribbon thickness
- divider → wordmark: ~0.75 ribbon thickness

## Wordmark

**M365 Hochschulcommunity**

`M365` is the compact technical anchor; `Hochschulcommunity` carries the identity.

Optional working claim:

> Gemeinsam weiter mit offenen Lösungen.

Typography hierarchy:

- `M365` — Manrope 800
- `Hochschulcommunity` — Manrope 500–600
- claim — Manrope 400

The first two lines are tightly stacked. The claim is substantially smaller and may be omitted in compact applications.

## Typography

Primary: **Manrope**. Fallback: Helvetica Neue / Arial / sans-serif.

Strong hierarchy, compact headlines, calm body text. Typography should carry more weight than decorative UI elements.

## Colours

- Deep Green `#0F4D3B`
- Jade `#2E7D6B`
- Mint `#88BDA7`
- Soft Green `#D7E8E1`
- Tint `#EEF5F2`
- Lavender `#E9E6F3`
- Dark Navy `#172B3A`
- White `#FFFFFF`

Avoid a Microsoft-blue identity, generic SaaS gradients or decorative colour noise.

## Layout

Swiss/editorial rather than dashboard-like:

- generous white space
- clear grids
- thin rules
- precise alignment
- few deliberate colour fields
- no floating SaaS cards
- no excessive rounded corners

The chevron is allowed to break the grid and introduce movement, but should not become wallpaper.

## Line system

- primary rule: `1px #172B3A`
- secondary rule: `1px #C9D3D0`
- accent rule: `2–3px #2E7D6B`

Prefer rules, spacing and alignment over boxes.

## Diagonal language

Use one recurring diagonal angle derived from the chevron, approximately **35–38°**.

It may shape image crops, document hero areas and occasional section transitions. Avoid unrelated diagonal angles.

## Shared-layer visual

The canonical conceptual illustration shows four institutional frames of different heights and positions crossed by one horizontal shared layer.

The institutions remain visually distinct. The shared layer carries:

> knowledge · tools · practice

The graphic should communicate federation rather than centralisation: local tenant, local rules and local responsibility remain intact.

## Image language

Prefer architecture, infrastructure and real higher-education environments. Use calm, graphic crops, often monochrome or lightly desaturated.

Avoid:

- staged teamwork stock photography
- handshake imagery
- generic cloud graphics
- smiling laptop teams

Photos may use the canonical diagonal crop, but not rounded corners or decorative shadows.

## Governance language

Current coordination:

**Kai Boschung · Lysann Deutschmann · Achim Imboden**

Use `Coordination` or `Coordinating Board` discreetly. The visual language should communicate stewardship, not hierarchy or ownership.

## Usage rules

Do not:

- put a circle or badge around the mark
- add Swiss-cross motifs
- make the mark 3D
- introduce gradients
- use the chevron as every bullet or navigation arrow
- repeat it decoratively across every section
- animate it continuously

The strength of Open Layers comes from restraint and repetition of a few precise mechanics.

## Scale guidance

### Website

- navigation mark: 28–34 px
- larger hero use: 80–160 px

### A4

- mark width: 12–16 mm
- horizontal lockup width: ~48–62 mm

### Micro

Use `chevron-micro.svg` below roughly 24 px if the full mark loses clarity.

## Print

The primary materials are HTML documents with exact A4 print layouts. Screen and print are views of the same source content. The canonical artefact stays editable in the repository; PDF is an export.
